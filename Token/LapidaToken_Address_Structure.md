# Lapida Token Address Structure & Distribution

## 1. Контракты токенов

Каждый токен — отдельный смарт-контракт, с уникальным адресом после деплоя:

- **LPDToken (Stablecoin)**: адрес появляется после деплоя (например, 0x...LPD)
- **MLPDToken (DeFi/Utility)**: адрес появляется после деплоя (например, 0x...MLPD)
- **GLPDToken (Governance)**: адрес появляется после деплоя (например, 0x...GLPD)

*Рекомендация: деплой каждого токена с owner-адресом под контролем команды или мультисиг-кошелька.*

---

## 2. Адреса для распределения

### Для прозрачности и безопасности советуем использовать отдельные адреса/кошельки для каждой категории распределения:

| Категория             | Описание                          | Адрес/Тип             | Примечания                        |
|-----------------------|-----------------------------------|-----------------------|-----------------------------------|
| Owner (Владелец)      | Управление контрактом             | EOA/Multisig          | Для деплоя и администрирования    |
| Команда/фаундеры      | Доля команды, вестинг             | Multisig/EOA          | Вестинг контракт                 |
| Инвесторы             | Seed/Private/Public Sale          | EOA/Batch             | Адреса инвесторов                |
| Адвайзеры             | Доля адвайзеров                   | EOA                   | Вестинг контракт                 |
| Фарминг/стейкинг      | Награды, пулы ликвидности         | Smart Contract        | Staking/Farming Pool             |
| Резерв/DAO            | Резерв, управление экосистемой    | Multisig/Smart Contract | Для голосования и инвестиций  |
| Маркетинг/PR          | Маркетинговые цели                | EOA                   |                                   |
| Эскроу                | Для блокировки платежей            | Smart Contract        | Escrow Contract                   |

*EOA — обычный кошелек (Metamask, TrustWallet), Multisig — мультиподписной кошелек (Gnosis Safe), Smart Contract — контракт-ресивер.*

| Эскроу                         | Escrow смарт-контракт             | 1          |

## 4. Практика безопасности

- **Мультисиг для owner и резервов** — предотвращает единоличный доступ.
- **Вестинг-адреса** — исключают досрочный вывод токенов командой или адвайзерами.
- **Прозрачность** — все адреса и распределения публикуются в whitepaper и на сайте.
- **Смарт-контракты для DeFi и эскроу** — автоматизируют распределение, фарминг, платежи.

---

## 6. Итог

- Для каждого токена — отдельный адрес контракта.
- Для распределения токенов — отдельные адреса/кошельки по категориям.
- Для управления и безопасности — рекомендуется использовать мультисиг и смарт-контракты.
- Все адреса должны быть задокументированы и прозрачны для комьюнити и аудиторов.
