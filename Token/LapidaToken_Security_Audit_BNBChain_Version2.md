# Lapida Token — Security & Audit Report (Draft, BNB Chain)

---

## 1. Введение

Безопасность — приоритет Lapida Token.  
Все смарт-контракты и архитектура платформы спроектированы с учётом лучших практик индустрии, проходят внутренний и внешний аудит и реализуют защиту от типовых атак.

---

## 2. Ключевые меры безопасности

### 2.1. Смарт-контракты

- Использование проверенных open-source библиотек (OpenZeppelin, SafeMath, Governor, Timelock).
- Минимизация прав: mint/burn, управление резервом — только через multisig.
- Реализация вестинга через отдельные контракты; невозможность досрочного вывода.
- Все критические параметры — только через DAO и timelock.
- Публичность исходного кода: [github.com/lapida-project](https://github.com/lapida-project)

### 2.2. Мультисиг и Timelock

- Управление резервами, эмиссией, изменениями параметров — только по мультиподписи (Safe).
- Timelock-контракт — защита от мгновенных изменений, возможность отмены при обнаружении угроз.
- Минимальный кворум для принятия решений.

### 2.3. Аудит

- Внутренний аудит: проверка логики, тесты на reentrancy, overflow, underflow, фронтранинг, race conditions.
- Внешний аудит: заказ у сертифицированных компаний (SOLIDproof, Hacken, CertiK — по мере развития).
- Публикация отчетов на [lapida.one](https://lapida.one) и GitHub.

### 2.4. Инфраструктурная безопасность

- Хранение приватных ключей multisig у доверенных лиц/компаний, использование аппаратных кошельков.
- Регулярное обновление инфраструктуры, мониторинг адресов на подозрительные транзакции.
- Защита веб-интерфейса: SSL, защита от XSS, CSRF, DDoS.

---

## 3. Основные угрозы и механизмы защиты

| Тип угрозы              | Механизм защиты                                 |
|-------------------------|-------------------------------------------------|
| Reentrancy              | Использование OpenZeppelin ReentrancyGuard      |
| Overflow/Underflow      | SafeMath, тесты                                 |
| Неавторизованный mint   | Только через multisig и timelock                |
| Взлом приватных ключей  | Аппаратные кошельки, разделение доступа         |
| Мошенничество/фишинг    | Проверка адресов, обучение пользователей        |
| Атаки на DAO            | Кворум, timelock, публичность голосований       |

## 4. Аудитируемые контракты (список)

- LPD, MLPD, GLPD (токены)
- Вестинг-контракты (для всех категорий)
- Governor, Timelock, ProposalFactory (DAO)
- ReserveContract (обеспечение)
- Multisig (Safe)
- SaleContract (IDO/Pre-sale)

## 5. Публикация результатов аудита

- Итоги внутреннего аудита: публикуются на GitHub, доступны для проверки.
- Внешний аудит: отчёты публикуются на сайте и GitHub.
- Любые найденные уязвимости устраняются до запуска публичных продаж и интеграций.

## 6. Рекомендации пользователям

- Проверять адреса токенов и контрактов только на [lapida.one](https://lapida.one).
- Использовать аппаратные кошельки для хранения крупных сумм.
- Не раскрывать seed-фразы и приватные ключи.
- Сообщать о подозрительных действиях через службу поддержки.
